How it was built

Provisioned from the terminal

The hard requirement, and the first thing to get working. Auth0 comes up through Stripe Projects, not through a dashboard.

$ stripe projects create ovation
✓ project prj_ovation created

$ stripe projects add auth0
✓ Auth0 tenant ovation.us.auth0.com
✓ application Ovation Web · Universal Login enabled
✓ Organizations enabled · roles owner, member
✓ credentials written to .env.local

$ stripe projects add database
✓ Postgres ovation-db · DATABASE_URL written

$ stripe listen --forward-to localhost:3000/api/webhook
› ready · checkout.session.completed → issues the coin
Population one

Collectors

  • Plain Auth0 users, no organization
  • One identity across every seller, which is the whole product
  • Consent stored per coin, revocable at any time
  • Their collection is the thing other people browse
Population two

Sellers

  • Auth0 Organizations, one per seller
  • Members with Owner or Member roles
  • Invitations sent by Auth0, no shared logins
  • Permissions read from the token, checked server side
Why this is the pitch and not plumbing. A collector's identity is portable across every independent seller on Ovation. That is exactly what an identity provider is for, applied to something people would actually enjoy using. Bandcamp only manages it by owning the whole marketplace.

Stripe, in one line each

Checkout · the purchase that hands over the coin
Webhook · checkout.session.completed claims the next serial
Connect · payouts to the seller
Projects CLI · provisioned all of the above, plus Auth0
